# 图表类型选型指南

`generate.py --type` 支持六种图表。根据用户描述的语义选择，选错类型会明显影响生成质量。

## 选型速查表

| 用户描述中的信号 | 选择 | 典型场景 |
|---|---|---|
| "流程""步骤""先…再…""如果…就""审批""出餐流程" | `flowchart` | 业务流程、算法逻辑、审批流 |
| "谁和谁交互""调用时序""请求顺序""A 发消息给 B" | `sequence` | 接口调用链、登录/下单时序、协议交互 |
| "由哪些部分组成""层级""包含""拆解""组织结构" | `composition` | 系统组成分解、组织架构、产品模块树 |
| "模块关系""依赖""接口关系""组件之间" | `component` | 服务依赖图、模块耦合关系 |
| "分层架构""接入层/服务层/数据层""技术架构" | `architecture` | 系统技术架构图、分层部署图 |
| "不同角色/部门各自做什么""跨部门流程""谁负责哪一步" | `swimlane` | 跨职能协作流程、责任分工流程 |

## 各类型细节

### flowchart 流程图
- 元素：开始/结束（圆角）、处理步骤（矩形）、判断（菱形）、分支连线
- 布局：Graphviz dot 自动布局，默认自上而下
- 适合：有明确先后顺序和条件分支的过程
- 描述建议：按步骤顺序写，明确判断条件和每个分支的走向

### sequence 时序图
- 元素：参与者（ lifeline 顶部）、按时间自上而下排列的消息箭头
- 布局：纯手工等间距布局，参与者横向排列
- 适合：强调"交互时间顺序"而非数据结构的场景
- 描述建议：写清参与者有哪些，然后按顺序描述"A 向 B 发起 X，B 返回 Y"

### composition 组成图
- 元素：树形层级节点，父节点包含子节点
- 布局：纯手工树状布局
- 适合：整体-部分（part-of）关系，回答"这个东西由什么构成"
- 描述建议：用"包含/下设/分为"等词表达层级，层级不要超过 4 层

### component 组件（关系）图
- 元素：组件方框 + 依赖连线
- 布局：Graphviz dot 自动布局
- 适合：模块/服务之间的依赖与调用关系，回答"谁依赖谁"
- 描述建议：列出组件清单，再逐条写"A 依赖/调用 B"

### architecture 架构图
- 元素：水平分层（layer），每层内放若干组件
- 布局：纯手工分层布局
- 适合：按技术层次组织的系统架构
- 描述建议：先写有哪几层（如接入层、业务层、数据层），再写每层包含的组件

### swimlane 泳道图
- 元素：泳道（角色/部门）+ 道内流程节点 + 跨道连线
- 布局：纯手工网格布局
- 适合：一个流程中多个角色协作，强调责任边界
- 描述建议：先确定有哪些角色，再按顺序写每一步由哪个角色执行

## 模糊场景的取舍

- 既像"流程"又有"多角色" → 优先 `swimlane`；角色只是执行者、重点在分支逻辑 → `flowchart`
- 既像"组成"又像"架构" → 关注**物理/技术分层**用 `architecture`，关注**逻辑包含关系**用 `composition`
- "接口调用关系"没有明显时序、只想看依赖网 → `component`；想看一次完整调用的先后 → `sequence`
